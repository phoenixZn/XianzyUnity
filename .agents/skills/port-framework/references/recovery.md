# 回写备份与失败恢复

本文件在确认回写、准备写入或处理中途失败时读取。检查、复制、应用补丁及删除都逐条核对退出结果，任何恢复失败均停止并报告。

## 执行前备份

在游戏库 `git rev-parse --absolute-git-dir` 对应目录下，为本次操作创建独立的 `port-framework/<唯一操作标识>/`。先验证其绝对路径位于该 Git 目录内且不存在；不要覆盖上一次失败操作。备份不放进可提交的源码目录。

保存以下内容；小型清单用工具或显式 UTF-8 写入，不通过 Shell 重编码源码：

- `review.txt`：完整审核脚本输出和 `REVIEW_SHA256`。
- 操作记录：核心库、游戏库路径，原始 `CORE_HEAD`、`GAME_HEAD`，已确认文件集合、远程地址、提交说明及各阶段是否开始、是否完成。提交后补记 `PORT_COMMIT`。
- 范围外保护基线：记录范围外未提交路径的存在状态、文件哈希和暂存条目，供结束后核对；这些路径不参与复制、还原或提交。
- `files/`：按相同相对路径复制游戏库已确认文件的原始字节，包括未跟踪文件；清单记录每个路径原先是否存在及 SHA-256。删除项记录为不存在。遇到目录、重解析点、符号链接或子模块时停止，不把外部内容复制进来。
- `staged.patch`：游戏库已确认路径相对 `HEAD` 的暂存差异，单独记录 SHA-256；空补丁也需记录为空，不尝试应用：

```powershell
git --literal-pathspecs -C <游戏库> diff --cached --binary --no-ext-diff --no-textconv --no-renames --output=<备份目录>/staged.patch <已审核GAME_HEAD> -- <已确认路径>
```

备份完成后核对每个副本哈希与源一致，并重跑审核脚本核对快照。保留原始暂存状态，不能把它与工作区内容合并成同一份补丁。

## 核心库尚未提交

游戏库不应被清理。核心库若部分应用了补丁或复制了文件，只清理本次明确产生的变化：先确认当前改动与操作记录一致，没有用户后续编辑；再将已确认路径恢复到原始 `CORE_HEAD`，只删除本次复制且内容仍相同的原未跟踪文件。无法证明归属时不自动还原。

提交命令失败但钩子可能已经生成提交时，先检查实际 `HEAD`、父提交及内容；不得误按“尚未提交”清理。报告实际状态，保留备份。

## 核心库已提交，游戏库尚未清理

保留 `PORT_COMMIT` 和备份，游戏库原始改动保持原样。报告失败阶段与两库状态，不自动撤销核心库提交，也不重复创建相同回写提交。

## 游戏库已开始清理，合并未成功

1. 若本次操作产生了 merge 状态，先记录冲突路径，再 `git merge --abort`；检查退出码。不能 abort 既有或不明来源的合并。
2. 要求游戏库仍在 `master`，且 `HEAD` 等于原始 `GAME_HEAD`。逐个核对所选路径和暂存区仍处于本次清理产生的状态，范围外变化未被本次操作改动；若有后续编辑、未知部分清理结果或分支变化，不自动恢复，保留备份并报告。
3. 将可确认归属本次操作的已跟踪所选路径还原到原始 `GAME_HEAD`，以此作为恢复暂存状态的基线。只操作清单中的路径，不触碰范围外暂存内容。
4. `staged.patch` 非空时先 `git apply --cached --check <staged.patch>`，成功后 `git apply --cached <staged.patch>`，只重建暂存区。应用前复核补丁 SHA-256、路径集合与备份记录一致。
5. 根据存在状态清单恢复工作区：原先存在的文件从 `files/` 按字节复制回来；原先不存在的路径，仅当当前文件可确认由本次清理产生且没有新编辑时删除。原未跟踪文件须恢复为未跟踪，不额外暂存。
6. 核对所有副本哈希、文件存在状态和所选路径暂存补丁均恢复到备份值，再检查范围外未提交改动及暂存状态没有被改变。

恢复成功也不声称回写任务已完成：核心库保留 `PORT_COMMIT`，游戏库恢复原始未提交状态。保留备份并报告两个提交基线、失败阶段及恢复结果。

## 续做与成功后的失败

续做时从操作记录中的 `PORT_COMMIT` 继续：核对核心库仍是该提交、游戏库仍是原始 `GAME_HEAD`，原始文件与暂存状态与备份一致，沿用已审核范围，从主流程的“清理游戏库前再 fetch”步骤开始；不可从头再生成一次回写提交。状态变化则停止自动续做，先重新审核。

合并已经成功时不再套用上述恢复。备份推送或结果检查失败时，保留现有提交与本次备份，分别报告合并结果和后续失败。
